## PART II: Scalable Website Architecture & Visual Framework

## Design Philosophy

**The "Repository & Registry" Model**
The architecture is built around a `Property` schema that functions as both a content model and a brand palette. Every project — whether Maple Leaf Garden City today or Green Valley Heights tomorrow — inherits the same design grammar. The brand does not change; the content rotates.

---

### 2.1 System Overview

```
coronaproperties-next/
├── app/
│   ├── (public)/
│   │   ├── layout.tsx           ← Root layout with JSON-LD brand schema
│   │   ├── page.tsx             ← Dynamic homepage, reads from SITE_CONFIG.activeProject
│   │   ├── about/
```

### 2.3 Dynamic Homepage Strategy

**Current:** `app/page.tsx` is static with hardcoded content.

**Scalable:** The homepage becomes a **project-aware composition**.

```tsx
app/page.tsx
├── imports SITE_CONFIG + getActiveProject()
├── Hero                         ← Reads from active project (name, tagline, hero, plot types)
├── NarrativeSection             ← Brand story (static, company-wide)
├── ProjectSpecs                 ← Dynamic: renders active project's masterplan figures
├── PlotShowcase                 ← Dynamic: loops through current project's plot tiers
├── AmenitiesShowcase            ← Dynamic: renders active project's amenity grid
├── LocationMap                  ← Dynamic: embeds Google Maps for active project
├── WhyInvest                    ← Static + dynamic investment logic
├── CTABanner                    ← Dynamic CTA for active project
└── LeadForm                     ← Pre-filled with active project name
```

**Key Insight:** Only one `page.tsx` exists. Only one `layout.tsx` exists. The content that changes per project is sourced through `lib/projects.ts`.

### 2.5 Visual Design Framework

#### 2.5.1 Typography Hierarchy

| Token | Weight | Use |
|-------|--------|-----|
| display-xl | 400–900 | Hero headlines, section dividers |
| display-lg | 400–900 | Project name introductions |
| display-md | 700 | Section headings |
| display-sm | 600 | Card titles |

**Font Pairing Rules:**
- **Playfair Display** — Emotional headlines ("Where Maple Canopy Meets Bangladeshi Aspiration")
- **Cormorant Garamond** — Elegant subheadings, pull quotes, serif captions
- **Inter** — Body copy, UI labels, metadata

**Ultra-Premium Touch:** Apply `font-variation-settings: "opsz" 48;` to Playfair Display at large sizes for optical sizing refinement.

#### 2.5.2 Color Architecture

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Primary Brand | `--navy` | `#0A1A3E` | Backgrounds, headers, authority |
| Accent Luxe | `--gold` | `#C9A96E` | CTAs, highlights, premium badges |
| Background | `--cream` | `#FAF8F4` | Sections, cards, readability |
| Text Primary | `--charcoal` | `#1A1A1A` | Body text |
| Status — Available | `emerald-600` | `#059669` | Plot availability |
| Status — Launching | `gold-600` | `#B8924A` | New phases |
| Status — Limited | `rose-600` | `#E11D48` | Scarcity signal |
| Surface White | `--surface` | `#FFFFFF` | Cards above cream |

**Innovation:** Introduce a `--surface-navy-025` (`rgba(10,26,62,0.025)`) for alternating section backgrounds to create depth without heavy contrast shifts.

### 2.6 Animation Strategy

**Luxury easing is critical.** Avoid ease-in-out. Use `cubic-bezier(0.22, 1, 0.36, 1)` everywhere.

| Interaction | Duration | Easing |
|-------------|----------|--------|
| Hero text reveal | 1.2s | luxury |
| Card hover lift | 0.6s | luxury |
| Button state change | 0.5s | luxury |
| Scroll reveal (section) | 0.8s | luxury |
| Image zoom on hover | 1.2s | linear |

**Parallax / Scroll Effects:**
- Hero background slideshow with slow zoom (scale 1.0 → 1.08) over 15 seconds
- Ornamental corner frames reveal with translateX/Y on scroll
- Image galleries with horizontal drag (Framer Motion `drag="x"`)

### 2.8 Performance & Technical Requirements

| Metric | Target |
|--------|--------|
| LCP (Largest Contentful Paint) | < 2.5s |
| CLS (Cumulative Layout Shift) | < 0.1 |
| FID (First Input Delay) | < 100ms |
| Time to Interactive | < 3.5s |
| Image Format | WebP / AVIF with fallback |

**Optimization Rules:**
- All hero images: `priority` + `sizes` with `fetchpriority="high"`
- Gallery images: `blur-up` loading with placeholder
- PDF brochure: Preload at `priority` for conversion pages
- Fonts: `display="swap"` with subset, `font-display: swap`
- Third-party scripts (analytics, chat): `defer` or after `onload`

### 2.10 Brand Voice Guidelines

| Element | Rule |
|---------|------|
| Sentence length | Max 28 words for body; max 12 words for headlines |
| Active voice | Mandatory |
| Numbers | Always spelled out for values < 10; digits for > 10 |
| Currency | `৳ 4.50 Crore` (not `৳ 45000000`) |
| Degrees | Use "Purbachal" not "Purbochal" in brand copy (house style) |
| Tone | Authoritative but warm. Aspirational but specific. Never desperate. |
| Avoid | "Buy now!", "Limited time!", "Hurry!" — use "Limited plots", "Registration open", "Secure your allocation" |
| Punctuation | sparing Oxford commas; never exclamation points in body copy |

## Summary

This strategy achieves two goals simultaneously:

1. **Marketing Copy:** A complete content system rooted in the actual technical specifications of the Maple Leaf Garden City project — disciplined, specific, and aspirational enough to attract high-net-worth individuals and NRB investors.

2. **Architecture:** A "single-project composite" design where the homepage and project pages render dynamically from a structured data registry. Adding the second project requires ~3,000 lines of JSON data and zero changes to component architecture, design tokens, or routing.

The design language — royal navy, warm gold, cream, and serif typography — functions as the brand's visual DNA, transferring identically to any future project.
