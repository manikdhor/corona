## 1. Project Preparation for Production

### 1.1 Audit Dependencies

- Remove dev-only dependencies from `dependencies` in `package.json` (e.g., TypeScript types, ESLint configs, PostCSS).
- Ensure only runtime packages remain in the `dependencies` object.
- Confirm `next.config.js` is optimized for production (no `reactStrictMode` overhead if not needed, proper `output` configuration).

**Example:**
```json
{
  "dependencies": {
    "next": "14.2.5",
    "react": "^18.3.1",
    "react-dom": "^18.3.1",
    "framer-motion": "^11.3.19",
    "lucide-react": "^0.424.0",
    "clsx": "^2.1.1",
    "tailwind-merge": "^2.4.0"
  },
  "devDependencies": {
    "@types/node": "^20.14.12",
    "@types/react": "^18.3.3",
    "@types/react-dom": "^18.3.0",
    "autoprefixer": "^10.4.19",
    "postcss": "^8.4.40",
    "tailwindcss": "^3.4.7",
    "typescript": "^5.5.4",
    "eslint": "^8.57.0",
    "eslint-config-next": "14.2.5"
  }
}
```

### 1.2 Create a Production Build Locally

```bash
npm run build
```

This generates the `.next/` directory with optimized production bundles. **Do not delete `.next/` before upload.**

### 1.3 Create a `.htaccess` File (if needed)

If Apache is the front-end web server, place a `.htaccess` file in `public/` to route requests correctly:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>
```

> **Note:** For Next.js custom server setups, modify rewrite rules accordingly.

### 1.4 Exclude Unnecessary Files

Add to `.gitignore` / exclude from upload:
- `node_modules/`
- `.git/`
- `.next/cache/`
- `__tests__/`
- `*.test.ts` / `*.spec.ts`
- `.env.local` / `.env.development.local`

### 1.5 Prepare `package.json` Scripts

Ensure a production start script exists:

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "next lint"
  }
}
```

The `start` script will be used by cPanel Node.js Selector.

## 2. File Upload Methods

### 2.1 Method A — cPanel File Manager (Recommended for Small Apps)

1. Log in to cPanel.
2. Open **File Manager**.
3. Navigate to your desired directory (e.g., `~/myapp/`).
4. Upload a ZIP archive of the project.
5. Extract the ZIP in place.
6. Delete the ZIP file afterward to save space.

### 2.2 Method B — FTP / SFTP

Use an FTP client (FileZilla, WinSCP, Cyberduck):

- **Host:** `ftp.yourdomain.com` or IP address
- **Protocol:** SFTP (preferred) or FTP
- **Port:** 22 (SFTP) or 21 (FTP)
- **Directory:** Navigate to the target folder and drag-and-drop files.

> **Tip:** Use binary transfer mode. Exclude `node_modules/` to save bandwidth and time.

### 2.3 Method C — Git Deployment

If the host supports Git integration:

1. In cPanel, open **Git™ Version Control**.
2. Click **Create** and paste your repository URL.
3. Set the deployment path.
4. Enable "Pull automatically" or manually trigger a pull after changes.

> **Caveat:** Some shared hosts have limited disk space. Ensure the `.git/` directory does not exceed your quota. Consider using a shallow clone:

```bash
git clone --depth 1 https://github.com/username/repo.git .
```

### 2.4 Required Directory Structure on Server

```
~/myapp/
├── .next/           # Generated by npm run build
├── public/          # Static assets
├── components/      # React components
├── app/             # Next.js App Router (if used)
├── lib/             # Utilities
├── package.json
├── package-lock.json
├── next.config.js
├── server.js        # Custom server (if applicable)
├── .htaccess        # Apache rewrite rules
└── ecosystem.config.js  # Optional: PM2 config
```

## 3. Configuring the Application Entry Point in cPanel

### 3.1 Open Node.js Selector

1. Log in to cPanel.
2. Navigate to **Software** → **Setup Node.js App** (or **Node.js Selector**).
3. Click **Create Application**.

### 3.2 Application Settings

| Field | Value |
|-------|-------|
| **Node.js version** | 18.x, 20.x, or as required by `package.json` engines field |
| **Application mode** | Production |
| **Application root** | `/home/username/myapp/` |
| **Application URL** | `https://yourdomain.com` or subdomain |
| **Application startup file** | `server.js` or `index.js` (for custom server) |
   - **OR** for Next.js standalone: leave blank and use command below |
| **Passenger log file** | Leave default or specify `~/myapp/logs/app.log` |

### 3.3 Startup File for Next.js

For standard Next.js apps without a custom server:

- **Startup file:** `node_modules/next/dist/bin/next`
- **Arguments:** `start -p $PORT`

However, many shared hosts require an explicit entry point. Create a wrapper file `server.js` in the project root:

```javascript
const { createServer } = require('http');
const next = require('next');

const dev = process.env.NODE_ENV !== 'production';
const hostname = 'localhost';
const port = process.env.PORT || 3000;

const app = next({ dev, hostname, port });
const handle = app.getRequestHandler();

app.prepare().then(() => {
  createServer(async (req, res) => {
    try {
      await handle(req, res);
    } catch (err) {
      console.error('Error occurred handling', req.url, err);
      res.statusCode = 500;
      res.end('internal server error');
    }
  }).listen(port, () => {
    console.log(`> Ready on http://${hostname}:${port}`);
  });
});
```

> **Alternative:** If using Next.js standalone output, modify `next.config.js`:

```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'standalone',
};

module.exports = nextConfig;
```

Then use the standalone server as the startup file.

### 3.4 Save and Launch

1. Click **Create** or **Save**.
2. After creation, click **Run NPM Install** (or use the provided button).
3. Once dependencies are installed, click **Start App**.

## 4. Installing Dependencies on the Server

### 4.1 Using cPanel Node.js Selector

- After creating the app, cPanel typically displays an **"Run NPM Install"** button.
- Click it. cPanel runs `npm install --production` in the application root.
- Monitor the output for errors (permissions, memory limits).

### 4.2 Manual Installation via SSH

If SSH access is available:

```bash
cd ~/myapp
npm install --production
```

### 4.3 Handling Native Modules

Some packages require compilation (e.g., `sharp`, `bcrypt`, `canvas`). On shared hosts:

- Check if the host has required libraries (`libvips` for sharp, `python` for node-gyp).
- If compilation fails, use prebuilt binaries:

```bash
npm install sharp --build-from-source=false
```

- Or switch to pure-JS alternatives:
  - `bcrypt` → `bcryptjs`
  - `canvas` → `jimp`

### 4.4 Install Memory Issues

Shared hosts often limit memory (e.g., 512MB). If `npm install` fails:

```bash
NODE_OPTIONS=--max_old_space_size=256 npm install --production
```

Or install in smaller batches:

```bash
npm install --production --no-optional
```

## 5. Managing Environment Variables

### 5.1 Using cPanel Environment Variables

1. In **Setup Node.js App**, click the **"Environment Variables"** button (or pencil icon).
2. Add variables:

| Key | Value |
|-----|-------|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | `mysql://user:pass@localhost:3306/dbname` |
| `NEXTAUTH_SECRET` | `your-secret-here` |
| `NEXTAUTH_URL` | `https://yourdomain.com` |
| `API_KEY` | `your-api-key` |

3. Save changes.
4. **Restart the application** for changes to take effect.

### 5.2 Using `.env` File (Alternative)

Create a `.env` file in the project root on the server:

```env
NODE_ENV=production
DATABASE_URL=mysql://username:password@localhost:3306/database_name
NEXTAUTH_SECRET=randomly-generated-secret-key-here
NEXTAUTH_URL=https://yourdomain.com
NEXT_PUBLIC_APP_URL=https://yourdomain.com
```

> **Security:** Add `.env` to `.gitignore`. Never commit secrets. Ensure the file is **not** served publicly (place it outside `public/`).

### 5.3 Reading Environment Variables in Next.js

```javascript
// app/lib/config.js
export const config = {
  databaseUrl: process.env.DATABASE_URL,
  appUrl: process.env.NEXT_PUBLIC_APP_URL,
};
```

> **Important:** Only variables prefixed with `NEXT_PUBLIC_` are exposed to the browser. Keep secrets server-only.

### 5.4 Restart After Changes

After modifying environment variables:

1. Go to **Setup Node.js App**.
2. Click **Restart** or **Stop** then **Start**.
3. Or via command line: touch `~/myapp/restart.txt` (Passenger) or use cPanel's restart button.

## 6. Establishing Database Connections

### 6.1 Create Database in cPanel

1. Open **MySQL® Databases** in cPanel.
2. Create a new database: `coronodb`.
3. Create a database user: `coronouser`.
4. Assign a strong password.
5. Add the user to the database and grant **ALL PRIVILEGES**.

### 6.2 Connection String Formats

**MySQL / MariaDB:**
```
DATABASE_URL=mysql://coronouser:SecurePass123!@localhost:3306/coronodb
```

**PostgreSQL (if supported):**
```
DATABASE_URL=postgresql://coronouser:SecurePass123!@localhost:5432/coronodb
```

**MongoDB (Atlas or self-hosted):**
```
DATABASE_URL=mongodb+srv://user:pass@cluster.mongodb.net/coronodb
```

### 6.3 Database Client Libraries

Ensure your `package.json` includes the correct driver:

```json
{
  "dependencies": {
    "mysql2": "^3.6.0",
    "pg": "^8.11.0",
    "mongoose": "^8.0.0"
  }
}
```

### 6.4 Example Database Connection (Next.js API Route)

```javascript
// app/api/properties/route.js
import mysql from 'mysql2/promise';

const connection = await mysql.createConnection({
  host: process.env.DB_HOST || 'localhost',
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
});

const [rows] = await connection.execute('SELECT * FROM properties');
return Response.json(rows);
```

### 6.5 Remote Database Connections

If the database is on a different server:

- Add the remote server IP to **cPanel → MySQL Databases → Remote MySQL**.
- Use the remote hostname in the connection string instead of `localhost`.
- Ensure firewall rules allow port 3306 (MySQL) or 5432 (PostgreSQL).

### 6.6 Database Migration

For schema changes, run migrations manually:

```bash
# If using a migration tool like knex or drizzle
npm run migrate
```

If migrations must run on the host:

1. Upload migration files.
2. Create a temporary API route or script that runs once.
3. Access it via browser, then remove/disable it.
4. Or run via SSH: `node -e "require('./db/migrate').up()"`

## 7. Post-Deployment Validation

### 7.1 Verify Application Status

1. In cPanel Node.js Selector, check the **Status** column.
2. Ensure it shows **"Running"** (not "Stopped" or "Error").

### 7.2 Check Application Logs

1. Click the **"Log"** button next to your app.
2. Look for:
   - `Ready on http://localhost:PORT`
   - Any startup errors.
   - Failed module imports.

### 7.3 Test the Live URL

- Visit `https://yourdomain.com`.
- Check all routes.
- Verify static assets (images, CSS, JS) load correctly.
- Test API endpoints.

### 7.4 Verify Environment Variables

Create a temporary diagnostic route:

```javascript
// app/api/health/route.js (REMOVE AFTER TESTING)
export async function GET() {
  return Response.json({
    nodeEnv: process.env.NODE_ENV,
    databaseUrl: process.env.DATABASE_URL ? '[SET]' : '[NOT SET]',
    timestamp: new Date().toISOString(),
  });
}
```

Visit `https://yourdomain.com/api/health` and confirm variables are loaded.

### 7.5 Performance Checks

- Run Lighthouse audit in Chrome DevTools.
- Check Time to First Byte (TTFB).
- Verify images are optimized (`next/image`).

## 8. Troubleshooting Common Deployment Errors

### 8.1 Application Fails to Start

**Symptom:** Status shows "Error" or the app crashes immediately.

**Solutions:**
- Check the application log in cPanel for the exact error message.
- Verify Node.js version compatibility (Next.js 14 requires Node.js 18.17+).
- Ensure the startup file path is correct and the file exists.
- Confirm `package.json` scripts are valid.

```bash
# Test locally first
npm run build && npm run start
```

### 8.2 500 Internal Server Error

**Symptom:** All routes return 500.

**Solutions:**
- Check logs for unhandled promise rejections.
- Verify database credentials in environment variables.
- Ensure file permissions are correct:
  ```bash
  chmod 755 *.js
  chmod 644 package.json
  chmod 600 .env
  ```
- Ensure `public/` files are readable by the web server user.

### 8.3 Module Not Found Errors

**Symptom:** `Error: Cannot find module 'xyz'`

**Solutions:**
- Run `npm install` again via cPanel.
- Ensure `node_modules/` was fully uploaded or installed.
- Check for case sensitivity issues (Linux servers are case-sensitive).

```bash
# Verify module exists
ls node_modules/xyz
```

### 8.4 Port Already in Use

**Symptom:** `Error: listen EADDRINUSE: address already in use`

**Solutions:**
- Do not hardcode ports. Always use `process.env.PORT`.
- Ensure no other apps on the account use the same port.
- Restart the app from cPanel.

### 8.5 Out of Memory Errors

**Symptom:** `JavaScript heap out of memory` or `FATAL ERROR: CALL_AND_RETRY_LAST Allocation failed`

**Solutions:**
- Increase Node.js memory limit:
  ```bash
  export NODE_OPTIONS=--max_old_space_size=512
  ```
- Optimize Next.js build (`output: 'standalone'` reduces memory footprint).
- Remove unnecessary dependencies.
- Contact host to increase memory quota.

### 8.6 Permission Denied Errors

**Symptom:** `EACCES: permission denied`

**Solutions:**
- Set correct ownership:
  ```bash
  chown -R username:username ~/myapp/
  ```
- Set correct permissions:
  ```bash
  find ~/myapp -type d -exec chmod 755 {} \;
  find ~/myapp -type f -exec chmod 644 {} \;
  chmod 600 ~/myapp/.env
  ```

### 8.7 Static Assets Not Loading (404)

**Symptom:** CSS, JS, or images return 404.

**Solutions:**
- Verify files exist in `public/` or `.next/static/`.
- Check `.htaccess` rewrite rules.
- Ensure `next.config.js` does not block asset paths.
- For Next.js Image component, ensure domains are whitelisted:
  ```javascript
  // next.config.js
  images: {
    remotePatterns: [
      { hostname: 'yourdomain.com' },
      { hostname: 'cdn.example.com' },
    ],
  }
  ```

### 8.8 Database Connection Refused

**Symptom:** `ECONNREFUSED` or `ER_ACCESS_DENIED_ERROR`

**Solutions:**
- Confirm database server is running (`mysqladmin ping`).
- Verify username, password, and database name in cPanel.
- Ensure the database user has privileges on the database.
- If using `localhost`, try `127.0.0.1` or the actual MySQL hostname provided by the host.
- Check if remote MySQL access is needed and configured.

### 8.9 Application Restarts Continuously

**Symptom:** App goes from "Running" to "Stopped" repeatedly.

**Solutions:**
- Check for uncaught exceptions in logs.
- Verify `package.json` `start` script works outside cPanel.
- Ensure no infinite loops in application code.
- Check if the app exceeds execution time limits (some hosts kill processes after 5 minutes).

### 8.10 HTTPS / SSL Issues

**Symptom:** Mixed content warnings or SSL certificate errors.

**Solutions:**
- Install SSL certificate via cPanel **SSL/TLS**.
- Redirect HTTP to HTTPS in `.htaccess`:
  ```apache
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
  ```
- Ensure `NEXTAUTH_URL` and `NEXT_PUBLIC_APP_URL` use `https://`.
